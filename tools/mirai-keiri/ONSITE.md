## 鉄則（これだけは守る）

> ### 🛑 最終承認は絶対に押さない
>
> FB-Web は **データ登録 → 一時保存 → 登録 → 一次承認 → 最終承認（送信）** の
> 多段構成。**銀行にデータが行くのは「最終承認」だけ。**
> テストは必ず **一時保存** まで。終わったら
> ［総合振込］→［取引状況照会/変更/取消］から**削除する**。
>
> - 一時保存 … 送信されない。**ここで止める**
> - 登録（取引パスワード入力）… まだ送信されない。承認待ちになる
> - 一次承認 … まだ送信されない
> - **最終承認 … 送信される。触らない**

- 本番データの隣で作業しない。テストは必ず**メモ欄に `TEST` と明記**する
- 画面は撮る。あとで「あれ何だったか」を潰すため
- 個人データを含みうる請求書は院外に出さない（別章第5条第1項）

## ⑧ 現場テスト（⓪がOKで、②の仕様が取れた場合のみ）

**必ず一時保存で止める。**

1. [ ] 実際の請求書3〜5通から `invoices.csv` を手で作る（この段階では手入力でよい）
2. [ ] `payees.csv` を④の出力から作る（対象3〜5社だけでよい）
3. [ ] `requester.json` に③で確認した委託者コードと出金口座を入れる
4. [ ] 実行:
   ```
   python3 mirai_keiri.py --master payees.csv --invoices invoices.csv \
       --config requester.json --date <振込指定日> --route screen --out out/
   ```
5. [ ] `out/振込一覧表_*.xlsx` を開き、**経理担当と金額を1件ずつ突き合わせる**
6. [ ] FB-Web で `［データ登録］→ 金額入力 →［金額外部取込］` に②の仕様で作った
      CSVを取込む
7. [ ] **画面の金額が振込一覧表と全件一致するか**を確認 → 一致 / 不一致（差分: ______）
8. [ ] メモ欄に `TEST` と入力して **［一時保存］**
9. [ ] `［取引状況照会/変更/取消］` で内容を再確認
10. [ ] 🛑 **テストデータを削除する**
11. [ ] 削除できたことを確認 → 完了 / 残っている
